1. OBJETIVO
================================================================================

1.1 OBJETIVO GENERAL:
Disenar, programar e implementar en equipo una plataforma web integral de foro 
comunitario e interactivo con estetica clasica de los anos 2000 (estilo vBulletin 
y phpBB), sustentada sobre una arquitectura desacoplada de alto rendimiento 
compuesta por un Backend en PHP nativo (API REST) y una base de datos NoSQL 
orientada a documentos (MongoDB Atlas), con despliegue en la nube, compatibilidad 
movil total y un sistema innovador de ciclo de vida de mensajes para optimizacion 
de almacenamiento.

1.2 OBJETIVOS ESPECIFICOS:
1. Desarrollar una API REST robusta en PHP nativo (Backend - Enzo) mediante un 
   enrutador central (Single Entry Point), procesando peticiones HTTP (GET, POST), 
   manejando respuestas estructuradas en JSON, control de cabeceras CORS y codigos 
   de estado sin depender de frameworks externos.
2. Implementar Persistencia NoSQL con MongoDB (Backend - Enzo) para las 
   colecciones de hilos y respuestas, aplicando consultas optimizadas, inserciones 
   atomicas, ordenamiento cronologico e indexacion por identificadores ObjectId.
3. Crear una mecanica de Supervivencia y Auto-Purgado (Bump Limit Gamificado): 
   cada hilo nace con limite inicial de 300 mensajes ampliable por votacion 
   comunitaria (+100 msgs hasta 3 veces), con auto-borrado atomico al llegar al 
   tope para no saturar el espacio gratuito en la nube.
4. Disenar el HUD y Maquetacion Retro (HUD/UI - Ignacio): Crear la identidad 
   visual inspirada en el ano 2002 con paleta retro, tablas con cabeceras en 
   degradado, cursores SVG pixelados de Windows 98 y diseno responsive.
5. Construir una Interfaz SPA Responsive (Frontend - Ivan y Enzo): Desarrollar el 
   frontend en JavaScript Vanilla (fetch asincrono y Hash Routing), brindando 
   una experiencia fluida sin recargas de pantalla y adaptada a celulares.
6. Desarrollar un sistema de perfiles descentralizado mediante localStorage 
   (Frontend - Ivan y Enzo), permitiendo a cada usuario personalizar su propio 
   alias y rango desde su dispositivo.
7. Testing y Control de Calidad (QA - Ortiz): Ejecutar pruebas continuas de 
   usabilidad, validacion de formularios, deteccion de errores en celulares y 
   verificacion de la integridad de datos en la nube.
8. Desplegar la plataforma en la nube (DevOps - Enzo): Docker + Render + 
   MongoDB Atlas con integracion continua (CI/CD con GitHub) y seguridad de 
   credenciales por variables de entorno (MONGODB_URI).

2. DESCRIPCION DEL SISTEMA
================================================================================

2.1 VISION GENERAL:
ForoPrueba2002 es una plataforma de debate tematico que combina la nostalgia 
visual de principios del 2000 con estandares y tecnologias modernas. Permite 
navegar por categorias (Charla General, Tecnologia, Videojuegos), crear temas, 
responder en tiempo real, buscar contenido por palabras clave y salvar hilos 
valiosos del borrado mediante votos comunitarios.

ARQUITECTURA:
[ Navegador Web / Smartphone ]
       |
       | (Peticiones HTTP GET / POST - JSON)
       v
[ Frontend SPA: HTML5 + CSS Retro (Ignacio) + JS (Ivan/Enzo) ]
       |
       | (Llamadas asincronas con fetch API)
       v
[ Backend API REST: PHP 8.2+ en Contenedor Docker (Enzo) ]
       |
       | (Driver Oficial MongoDB PHP / TLS Seguro)
       v
[ Base de Datos NoSQL: MongoDB Atlas Cluster M0 (Nube) ]
       ├── Coleccion 'hilos' (Temas principales y limites de vida)
       └── Coleccion 'respuestas' (Comentarios vinculados por ObjectId)
       |
[ Control de Calidad & Pruebas en Vivo: Ortiz ]

2.2 COMPONENTES TECNICOS:
- Backend & Router REST (public/index.php) [Enzo]: Recibe todas las peticiones 
  bajo el patron Front Controller y responde en formato JSON a rutas como 
  /api/forum, /api/category/{id}, /api/threads, /api/thread/{id}, 
  /api/thread/{id}/reply, /api/thread/{id}/extender y /api/search.
- Capa de Base de Datos (config/database.php) [Enzo]: Conexion Singleton a 
  MongoDB Atlas para reutilizar una unica conexion eficiente y segura.
- Mecanica de Supervivencia [Enzo, Ivan e Ignacio]: Controla el espacio en 
  disco. Los hilos nacen con 300 mensajes. Al juntar 3 votos se extienden +100 
  mensajes (maximo 3 veces). Al llegar al limite final se ejecuta deleteOne() y 
  deleteMany() automaticamente en MongoDB, con feedback visual de confeti.
- Diseno de HUD y Estilos Retro (classic.css) [Ignacio]: Paleta retro estilo 
  vBulletin 2002, cursores SVG de Windows 98 y adaptabilidad responsive con 
  media queries para celulares.
- Frontend SPA y Logica de Cliente (forum.js) [Ivan y Enzo]: Hash routing 
  (#home, #category/..., #thread/..., #profile), gestion de perfiles con 
  localStorage y autorelleno de autor.
- Control de Calidad y Pruebas [Ortiz]: Pruebas en smartphones reales (Android/iOS), 
  deteccion de bugs de identidad y pruebas de estres del auto-purgado.

3. CRONOGRAMA DE TRABAJO (3 SEMANAS EJECUTADAS + 2 SEMANAS PROYECTADAS)
================================================================================

ETAPA EJECUTADA (3 SEMANAS DE DESARROLLO INTENSIVO EN EQUIPO):

- SEMANA 1: PLANIFICACION, ARQUITECTURA Y CONEXION DE DATOS
  * Coordinacion y Requerimientos (Lider: Enzo): Definicion de arquitectura y tareas.
  * Modelado NoSQL (Enzo): Documentos en MongoDB con claves ObjectId.
  * Prototipado de HUD (Ignacio): Bocetos retro y esquema de tablas para la interfaz.
  * Configuracion del Entorno (Enzo e Ivan): PHP 8.2+, Composer, driver oficial de 
    MongoDB y configuracion de php.ini en Windows.
  * Testing Inicial (Ortiz): Verificacion de lectura y escritura local en MongoDB.

- SEMANA 2: DESARROLLO DEL BACKEND REST Y LOGICA DE NEGOCIO
  * Router REST & Endpoints (Enzo): Programacion del enrutador central en PHP para 
    solicitudes GET y POST con respuestas JSON.
  * Algoritmo de Supervivencia (Enzo e Ivan): Logica de votacion comunitaria (+100 
    msgs) y auto-purgado en MongoDB (deleteOne y deleteMany).
  * Maquetacion Base del HUD (Ignacio): Estilos en classic.css, tablas y cursores.
  * Buscador por Palabras Clave (Enzo): Endpoint con expresiones regulares (Regex).
  * Pruebas de Backend (Ortiz): Validacion de endpoints y control de errores HTTP.

- SEMANA 3: FRONTEND SPA, RESPONSIVIDAD MOVIL, DESPLIEGUE CLOUD Y SEGURIDAD
  * Frontend SPA (Ivan y Enzo): Controlador forum.js con Hash Routing y fetch.
  * Adaptabilidad Movil del HUD (Ignacio y Ortiz): Ajuste de media queries para 
    disposicion vertical tactil en celulares.
  * Sistema de Perfiles (Ivan y Enzo): Modulo localStorage para identidad por 
    dispositivo y autorelleno de campos.
  * Despliegue Cloud & DevOps (Enzo): Dockerfile, integracion continua (CI/CD) con 
    GitHub y hosting en Render.com conectado a MongoDB Atlas.
  * Auditoria de Seguridad (Enzo): Sanitizacion de credenciales con variables de 
    entorno (MONGODB_URI) y proteccion contra ataques XSS.
  * Pruebas de Campo (Ortiz): Pruebas en smartphones reales de los integrantes, 
    detectando y validando la solucion a problemas de visualizacion e identidad.

ETAPA PROYECTADA A FUTURO (2 SEMANAS DE CIERRE):

- SEMANA 4: PRUEBAS MASIVAS, BETA TESTING Y MODERACION
  * Pruebas de estres con companeros de curso en Render y MongoDB Atlas (Ortiz y Equipo).
  * Pulido de detalles visuales del HUD (Ignacio).
  * Modulo de moderacion y filtrado de palabras basicas (Enzo e Ivan).

- SEMANA 5: OPTIMIZACION FINAL, DOCUMENTACION Y PRESENTACION
  * Optimizacion de indices en MongoDB para velocidad de consulta (Enzo).
  * Elaboracion de diapositivas y material de exposicion (Todo el Equipo).
  * Demostracion en vivo y defensa formal del proyecto ante los docentes.
